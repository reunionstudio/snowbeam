# Snowbeam 0.2.0a4

Draft for the next release. Iterate locally with `make dev`; rebuild and validate
the final commit before publishing these downloads.

Start a connection from one you already have.

**Add** opens a blank form with **Clone from** at the top. Choose an existing
connection, edit the filled-in settings, and save under a new name. Or select a
connection and choose **Clone** (Shift+`c`) to open the same form with its source
already selected. The source selector and Save/Cancel controls stay visible
while the fields scroll.

The CLI supports both routes:

```sh
snowbeam connections add reporting --clone-from work --warehouse REPORTING_WH
snowbeam connections clone work another-client --account OTHERORG-PROD --user JANE
```

Cloning uses saved editable settings from the current Snowflake configuration.
Credentials, credential file paths, vault bindings, environment overrides, and
unshown configuration options are not copied. The source profile and default
connection stay intact. The new connection starts unverified; this workflow does
not create a Snowflake user or grant access. See the
[connection guide](../user-guide.md#add-or-clone-a-connection).

## Install or upgrade

On macOS, install with `brew install reunionstudio/tap/snowbeam`. Existing official
Homebrew installations can use **Updates → Check now → Update and restart**, or
close Snowbeam and run `brew update` and `brew upgrade reunionstudio/tap/snowbeam`.

On Linux or Omarchy with uv:

```sh
uv tool install --reinstall https://github.com/reunionstudio/snowbeam/releases/download/v0.2.0a4/snowbeam-0.2.0a4-py3-none-any.whl
snowbeam --demo
```

This remains an alpha. The workflow is tested with isolated configuration and
synthetic data, including small-terminal use, source switching, save/cancel,
credential exclusion, source preservation, and CLI creation. Live Snowflake,
vault, hosted Linux CI, and actual Omarchy desktop validation remain pending.

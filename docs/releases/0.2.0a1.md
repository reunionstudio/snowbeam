# Snowbeam 0.2.0a1

Alpha release. This is an evaluation release for a dedicated test
account, with a synthetic demo that needs no credentials.

Snowbeam makes many Snowflake connections and individual agent identities easier
to organize across organizations and accounts. It is a local Python terminal
application for Linux and macOS, built first for Omarchy, and licensed under MIT.

## Included

Connection and identity inventories; client/owner/runtime labels; PAT metadata and
attention; policy evidence; reviewed managed-agent lifecycle plans; 1Password and
Bitwarden adapters; existing workload-identity bindings; runtime handoffs; CLI/JSON
commands; optional desktop launchers and reminders; and the pixel Snowbeam logo.
Includes configurable background refresh with persisted failure backoff, an
Updates panel with optional daily release checks, and Homebrew packaging tools.
Official Homebrew installations offer **Update and restart** with progress,
verification, and automatic reopening after the user's click. Other installations
show manual instructions. Release checks never install updates automatically.

Snowflake enforces access, vaults hold managed secrets, and an external runtime
runs the agent. Snowbeam does not provide OS isolation or provision cloud IAM.

## Install

On macOS with Homebrew:

```sh
brew install reunionstudio/tap/snowbeam
snowbeam --demo
```

Or, with uv installed, from the directory containing the downloaded release wheel:

```sh
uv tool install ./snowbeam-0.2.0a1-py3-none-any.whl
snowbeam --version
snowbeam --demo
```

The source archive is `snowbeam-0.2.0a1.tar.gz`. The release includes checksums and
the generated formula used by [the Homebrew tap](https://github.com/reunionstudio/homebrew-tap).
Omarchy and other Linux users can follow the [uv installation guide](../omarchy.md);
AUR packaging remains pending.
No DMG is included. Snowflake CLI and provider CLIs are separate
prerequisites for live workflows. See the [README](../../README.md) for installation,
upgrade, uninstall, and first-use behavior.

## Validation and known limits

- Local macOS ARM64 checks passed on Python 3.11, 3.13, and 3.14: 124 isolated
  tests on each version. See the [validation record](0.2.0a1-validation.md).
- Automated account/provider tests use synthetic responses and isolated files.
- The wheel and source archive are checked in clean temporary environments,
  including command discovery, package version, bundled icon, demo inventory,
  and headless terminal startup.
- Linux and macOS CI templates cover Python 3.11, 3.13, and 3.14. They are not
  enabled: GitHub authorization for workflow changes is pending. This alpha is
  checked locally; hosted Linux CI and live Omarchy validation remain pending.
- Local Homebrew install/upgrade and wheel upgrade trials retained synthetic
  configuration, token metadata, and operation history. The Homebrew trial used
  existing dependencies and a disposable revision; full dependency installation
  on a clean Mac and Intel macOS testing remain pending.
- The in-app installer and restart flow have isolated tests. A live button update
  between two published official-tap versions remains pending.
- Live Snowflake provisioning, real 1Password/Bitwarden writes, cloud workload
  authentication, and a real Omarchy desktop remain pending.
- macOS launchd and Linux systemd/desktop behavior have isolated tests; actual
  scheduler and notification delivery need manual validation.
- Runtime reports supplied by an operator are not signed Snowflake attestations.
- The metadata cache is not encrypted. Existing secrets in Snowflake configuration
  remain in that configuration and its backup. Forced termination can leave
  restricted temporary credential files requiring cleanup.

Earlier local builds reported `0.2.0`; no stable `0.2.0` was published. Reinstall the
chosen alpha artifact explicitly when moving from that private development build.

For issues, include the package and platform versions with a sanitized reproduction.
Report credential exposure and access-control problems through [SECURITY.md](../../SECURITY.md).

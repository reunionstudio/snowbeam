# Snowbeam 0.2.0a2

Give your Snowflake organizations and accounts names you recognize, plus local notes.
For example, `FLXH5C4T` can appear as **Acme Accounting LLC**.

Select an organization or account in the left tree and choose **Alias / notes**
(`n`). Save a friendly name and multiline notes. The inventory shows those names;
real Snowflake identifiers remain in details and are still used for connections
and clipboard copies. Identity search also matches aliases.

The CLI edits the same local records:

```sh
snowbeam labels organization FLXH5C4T --alias "Acme Accounting LLC"
snowbeam labels account FLXH5C4T-PROD --notes "Review access before monthly close."
```

Use identifiers already present in your inventory. Labels require no network
access, change no Snowflake objects or permissions, and do not alter connection
configuration. Keep credentials in your vault, never in notes.

## Install or upgrade

On macOS with Homebrew:

```sh
brew install reunionstudio/tap/snowbeam
snowbeam --demo
```

If already installed through the official tap, open **Updates**, check for this
release, and choose **Update and restart**. Manual upgrades also work with
`brew update` and `brew upgrade reunionstudio/tap/snowbeam` while Snowbeam is closed.

On Linux or Omarchy with uv:

```sh
uv tool install --reinstall https://github.com/reunionstudio/snowbeam/releases/download/v0.2.0a2/snowbeam-0.2.0a2-py3-none-any.whl
snowbeam --demo
```

See the [user guide](../user-guide.md#organization-and-account-aliases) for controls,
CLI flags, field limits, and storage paths. Existing profiles and local inventory
survive the upgrade. Opening this version upgrades the inventory database to
schema 4; earlier versions will reject it. Back up local state before downgrading.
Aliases and notes live in this database and are removed if it is deleted.

## Validation and limits

Tests use isolated synthetic data and fake Snowflake responses. The feature covers
storage migration, refresh/restart persistence, recognized account renames,
distinct account identities, field validation, CLI editing, and the actual terminal
forms, including keyboard use at 80 × 24. See the
[validation record](0.2.0a2-validation.md) for completed release checks.

This remains an alpha. Live Snowflake provisioning, real vault writes, cloud
workload authentication, hosted Linux CI, and an actual Omarchy desktop remain
unvalidated. Linux installation uses a portable Python wheel; no AUR package or
macOS DMG is included. Local inventory and notes are private to the filesystem
user but are not encrypted or synced between devices. JSON inventory exports
include aliases and notes.
